---
title: "第一次调用"
description: "创建一把 API Key，然后从 Agent 或脚本里拿到第一条真实结果"
---

三步：创建 Key → 选一种接入方式 → 看到结果。整个过程不需要写服务端代码。

## 1. 创建 API Key

打开[控制台](https://open-dev.bingyan.net/console/)，用 Hustoday 账号登录，新建一把 Key。名称写用途（例如 `Claude Code`），权限按需要勾选：

| 你想做什么 | 勾选的 Scope |
| --- | --- |
| 查课程、看评价 | `courses:public:read` |
| 查 1037wiki 资料 | `wiki:public:read` |
| 看 Hustoday 校园动态 | `hustoday:public:read` |
| 问"我今天有什么课" | `schedule:self:read` |
| 让 Agent 知道我是谁 | `profile:self:read` |

一次勾完也可以：[带预选的创建链接](https://open-dev.bingyan.net/console/?scope=courses:public:read&scope=wiki:public:read&scope=hustoday:public:read&scope=schedule:self:read&scope=profile:self:read)。

<Warning>
  Secret 只展示一次，形如 `byk_test_…`。保存到密码管理器或环境变量，不要提交到 Git，也不要贴进群聊。
</Warning>

## 2. 选一种接入方式

<Tabs>
  <Tab title="Agent（MCP）">
    平台的 MCP 入口是 `https://open-dev-api.bingyan.net/mcp`，用同一把 Key 做 Bearer Token。以 Claude Code 为例，在终端执行：

    ```bash
    claude mcp add --transport http open-bingyan https://open-dev-api.bingyan.net/mcp \
      --header "Authorization: Bearer byk_test_你的Key"
    ```

    或者把下面这段放进项目的 `.mcp.json`（Claude Code、Cursor、Codex 等都认这个格式）：

    ```json
    {
      "mcpServers": {
        "open-bingyan": {
          "type": "http",
          "url": "https://open-dev-api.bingyan.net/mcp",
          "headers": { "Authorization": "Bearer byk_test_你的Key" }
        }
      }
    }
    ```

    然后直接问：

    > 帮我看看「中国文化史」哪个老师评价最好，点名严不严？

    Agent 会调用 `search_courses` 和 `course_detail` 并给出带证据的回答。全部工具见 [MCP 工具](/mcp-tools)。
  </Tab>
  <Tab title="curl / 脚本">
    所有接口都是 `https://open-dev-api.bingyan.net/v1/...`，请求头带 `Authorization: Bearer <Key>`：

    ```bash
    export OPEN_BINGYAN_API_KEY="byk_test_你的Key"

    curl --request GET \
      --url "https://open-dev-api.bingyan.net/v1/courses/search?keyword=文化史" \
      --header "Authorization: Bearer $OPEN_BINGYAN_API_KEY"
    ```

    返回：

    ```json
    {
      "items": [
        {
          "name": "中国文化史",
          "teacher": "白杨等",
          "category": "中国与世界",
          "credit": "2",
          "quality": 1.21,
          "assessment_count": 44,
          "rollcall_way": "签到",
          "assessment_way": "考试",
          "has_assignment": "有作业"
        }
      ],
      "total": 4
    }
    ```

    每个路径需要哪个 Scope 见[能力与权限](/capabilities)，完整参数见 [API Reference](/api-reference/搜索公开课程)。
  </Tab>
  <Tab title="Agent Skill">
    如果你在写 Skill（WorkBuddy、Claude Code、Cursor、Codex 通用的 `SKILL.md` 格式），冰岩的 [hust-skills](https://github.com/BingyanStudio/hust-skills) 仓库里有一组基于本平台的 skill：选课参谋、我的课表、找资料、校园动态。

    ```bash
    git clone https://github.com/BingyanStudio/hust-skills.git
    cp -r hust-skills/skills/hust-timetable ~/.claude/skills/   # 或你的 Agent 的 skills 目录
    ```

    这些 Skill 会优先使用上面的 MCP 工具；没有 MCP 的环境下退回到脚本，从环境变量 `OPEN_BINGYAN_API_KEY` 读 Key。写自己的 Skill 时也建议这样做，不要把 Key 写进 Skill 文件。
  </Tab>
</Tabs>

## 3. 判断结果

- 拿到 JSON 就是成功。个人数据接口（课表、资料）始终返回 Key 所有者本人的数据，不接受 `cid`、学号等身份参数。
- `401 invalid_api_key`：Key 不完整、环境不对（`byk_test_` 的 Key 只能调 `open-dev-api`），或已撤销。
- `403 insufficient_scope`：这把 Key 没勾这个接口要的 Scope。Scope 创建后不可改，重新建一把带该 Scope 的 Key 再撤销旧的。MCP 工具遇到这种情况会直接告诉 Agent 缺哪个 Scope，并给出带预选的控制台链接。
- `503 upstream_unavailable`：上游校园服务没有响应，稍后重试。
- 上游自己的 4xx/5xx 会原样透传（例如羽球服务对没在它那里注册过的用户返回 `500 Failed to get user`），这类错误意味着你需要先在对应产品里有账号。
